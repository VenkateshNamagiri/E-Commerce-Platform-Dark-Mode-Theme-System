1.What is multipart/form-data and why is it different from a normal JSON request when uploading files?

Multipart/form-data is an HTTP request format used for sending files along with other form data. Unlike JSON, which 
is mainly designed for structured text data but multipart/form-data can carry the actual binary contents of an image file.

In this project, React creates a FormData object and adds the selected image:

const formData = new FormData()
formData.append('image', file)

await api.post('/api/upload', formData, {
  headers: {
    'Content-Type': 'multipart/form-data'
  }
})

A normal JSON request would look like:

api.post('/api/products', {
  name: 'Laptop',
  price: 50000,
  image_url: '/static/uploads/image.jpg'
})

That JSON request sends text/data, not the actual image file. Therefore, we use multipart/form-data to upload the image 
first and then store the returned image_url in the product.


2.How do you generate a unique filename for every upload? What would happen if you didn't?

I used Python's uuid.uuid4() to generate a unique filename for every uploaded image.

The code is:

import uuid

ext = file.filename.rsplit('.', 1)[-1].lower()
unique_name = f"{uuid.uuid4().hex}.{ext}"

For example, if the uploaded file is:

photo.jpg

it could be stored as:

a7f3c91e2b4d4c1a8e6f123456789abc.jpg

The reason for using a unique filename is to prevent different uploads from overwriting each other.

For example, if two admins upload files both named:

photo.jpg

and we simply saved them using the original filename, the second upload could overwrite the first image.

With UUIDs:

photo.jpg → 8a21...f3.jpg
photo.jpg → c91b...72.jpg

So both files remain separate.


3.What validation did you add to block non-image files or oversized files? Show the exact code.

I added validation for the file extension and configured a maximum file size of 2 MB.

The configuration is:

UPLOAD_FOLDER = 'static/uploads'
ALLOWED_EXTENSIONS = {'png', 'jpg', 'jpeg', 'webp'}
MAX_FILE_SIZE = 2 * 1024 * 1024  # 2 MB

os.makedirs(UPLOAD_FOLDER, exist_ok=True)
app.config['UPLOAD_FOLDER'] = UPLOAD_FOLDER

The function that checks the file extension is:

def allowed_file(filename):
    ext = filename.rsplit('.', 1)[-1].lower()
    return '.' in filename and ext in ALLOWED_EXTENSIONS

The upload route checks the file:

@app.route('/api/upload', methods=['POST'])
def upload_image():
    if 'image' not in request.files:
        return jsonify({"error": "No file provided"}), 400

    file = request.files['image']

    if file.filename == '':
        return jsonify({"error": "No file selected"}), 400

    if not allowed_file(file.filename):
        return jsonify({"error": "Invalid file type"}), 400

For the 2 MB limit, the important Flask configuration should be:

app.config['MAX_CONTENT_LENGTH'] = 2 * 1024 * 1024

This makes Flask reject requests larger than 2 MB.

Important: Simply defining:

MAX_FILE_SIZE = 2 * 1024 * 1024

does not enforce the limit by itself. It needs to be connected to Flask's request-size configuration, such as 
MAX_CONTENT_LENGTH, or checked manually.


4.Where does Flask store the uploaded file, and what URL pattern does the frontend use to display it afterward?

Flask stores uploaded images in:

static/uploads

This is configured using:

UPLOAD_FOLDER = 'static/uploads'

os.makedirs(UPLOAD_FOLDER, exist_ok=True)
app.config['UPLOAD_FOLDER'] = UPLOAD_FOLDER

After generating a unique filename, the file is saved using:

filepath = os.path.join(
    app.config['UPLOAD_FOLDER'],
    unique_name
)

file.save(filepath)

The backend then returns the image URL:

image_url = f"/static/uploads/{unique_name}"

return jsonify({"image_url": image_url}), 201

Because the folder is inside Flask's static directory, Flask automatically serves the image.

The frontend builds the complete URL using the backend address:

<img
  src={`http://localhost:5000${product.image_url}`}
/>

So if the database contains:

/static/uploads/a7f3c91e.jpg

the browser requests:

http://localhost:5000/static/uploads/a7f3c91e.jpg

This ensures the exact uploaded image is displayed every time instead of generating a random Picsum image.
