1.What is LIMIT and OFFSET in SQL?If you have 47 products and want page 3 with 8 per page, what are the exact LIMIT and OFFSET values?

---LIMIT tells to SQL how many records have to return.
---OFFSET tells to SQL how many records to skip before returning results.

The formula is:

OFFSET = (page - 1) × limit

If there are 47 products and we want page 3 with 8 products per page:

LIMIT = 8
OFFSET = (3 - 1) × 8
       = 16

So the SQL would be: LIMIT 8 OFFSET 16;

This means:

*Skip the first 16 products.
*Return the next 8 products.
*These correspond to products 17–24 in the ordered result set.
*The fact that there are 47 total products doesn't change the LIMIT or OFFSET for page 3.


2.Explain how useDebounce works.What does the cleanup function (return () => clearTimeout(timer)) do and why is it important?

useDebounce delays updating the value until the user has stopped changing it for a certain amount of time, such as 300 
milliseconds.

For example, when the user types:

l
la
lap
lapt
lapto
laptop

the hook starts a 300ms timer after each change.

But this part is very important:

return () => clearTimeout(timer)

The cleanup function cancels the previous timer whenever the value changes before the 300ms has finished.

So instead of making 6 API requests:

l       → request
la      → request
lap     → request
lapt    → request
lapto   → request
laptop  → request

the previous timers are continuously cancelled:

l       → start timer → cancelled
la      → start timer → cancelled
lap     → start timer → cancelled
lapt    → start timer → cancelled
lapto   → start timer → cancelled
laptop  → start timer → completes → API request

This is important because it prevents unnecessary API calls and reduces the load on the backend.


3.Why do you reset currentPage to 1 when the search term changes?

We reset the current page to 1 because a new search creates a new result set. The previous page number may not exist in
the new results, so starting from page 1 prevents empty or invalid results.

Suppose the user is currently on Page 4and then searches for: laptop

The search results are a new set of results. There might be only 1 or 2 pages of laptops.

If we stay on page 4, the backend might return:[]

even though matching products exist on page 1.

Therefore, when the debounced search term changes, we do:

useEffect(() => {
  setCurrentPage(1)
}, [debouncedSearch])

This ensures that every new search starts from the first page of the new result set.


4.Your Pagination component is used in two different pages. What props does it accept and how does the parent control which page is active?

Pagination is reusable because it doesn't manage the page itself. It receives the current page, total number of pages, 
and a callback from the parent. When the user clicks a page, it calls onPageChange, and the parent updates currentPage. 
This allows the same component to work for both products and orders.

The Pagination component accepts three props:

<Pagination
  currentPage={currentPage}
  totalPages={totalPages}
  onPageChange={setCurrentPage}
/>

The three props are:

currentPage — tells the component which page is currently active.
totalPages — tells it how many page buttons/pages to display.
onPageChange — a function that the component calls when the user selects another page.
The important point is that the parent component owns the page state.

For example, in Home.jsx:

const [currentPage, setCurrentPage] = useState(1);

Then:

<Pagination
  currentPage={currentPage}
  totalPages={totalPages}
  onPageChange={setCurrentPage}
/>

If the user clicks page 3, Pagination calls:

onPageChange(3)

which is actually:

setCurrentPage(3)

The parent's state becomes:

currentPage = 3

That state change causes the product-fetching useEffect to run again and request page 3 from the backend.

The same component can therefore be used in AdminOrders.jsx:

<Pagination
  currentPage={currentPage}
  totalPages={totalPages}
  onPageChange={setCurrentPage}
/>
